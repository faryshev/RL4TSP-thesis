# RL4TSP: воспроизводимые эксперименты

Проект содержит самодостаточный набор TSP-экспериментов: обучение моделей, сравнение с опорным решателем и диагностические проверки для анализа RL-подходов к задаче коммивояжера.

## Структура

- `src/rl4tsp/` - модели, обучение, POMO, TSP-решатели, графики и сохранение артефактов.
- `experiments/` - отдельные запускаемые скрипты.
- `configs/` - малые smoke-конфиги и full-конфиги для основных запусков.
- `Experiment_Launcher_and_Analysis.ipynb` - простой ноутбук для запуска и просмотра результатов.
- `run_experiments.sh` - полный TSP-запуск из командной строки.
- `tests/` - проверки корректности реализации.

## Эксперименты

1. Масштабирование: Attention, PointerNet, POMO и опорный решатель сравниваются по отклонению от опорного решения и времени.
2. Перестановочная эквивариантность: проверяется, сохраняется ли канонический тур после переименования городов.
3. Устойчивость к шуму координат: маршрут строится по зашумленным координатам, а качество оценивается на истинных координатах.
4. Reward-noise: обучение идет по зашумленной длине тура, а оценка проводится по истинной длине.
5. Энтропия политики и качество решения: проверяются энтропия, top1-top2 logprob sharpness и дисперсия длины при стохастическом декодировании.

## Быстрый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Full-запуски используют LKH через пакет `elkai`, который включен в `requirements.txt`. Если на конкретной машине `elkai` не ставится, можно временно заменить `reference_solver` в full-конфигах на `exact_or_nn_2opt`, но тогда большие TSP будут сравниваться с более слабым эвристическим референсом.

Smoke-запуск:

```bash
RL4TSP_SCALE=small bash run_experiments.sh
```

Полный запуск:

```bash
RL4TSP_SCALE=full bash run_experiments.sh
```

Каждый запуск пишет данные в `results/<run_id>/...`. Повторный запуск не перезаписывает существующий каталог, если явно не задано `RL4TSP_ALLOW_OVERWRITE=1`.
По умолчанию launcher использует `RL4TSP_TORCH_THREADS=4`, `PYTHONUNBUFFERED=1` и кэш Matplotlib в `.runtime-cache/matplotlib`. Если на машине больше ядер и обучение стабильно, число потоков можно увеличить, например `RL4TSP_TORCH_THREADS=8 RL4TSP_SCALE=full bash run_experiments.sh`.

## Основные выходы

- `models/*.pt` и `models/*.json` - сохраненные веса и метаданные.
- `logs/*_log.json` - логи обучения.
- `tsp_comparison/raw.csv`, `summary.csv` - масштабирование.
- `tsp_diagnostics/*_raw.csv`, `*_summary.csv` - перестановки, шум координат, внутренние сигналы политики.
- `tsp_reward_noise/raw.csv`, `summary.csv`, `models/*.pt` - reward-noise и веса всех обученных вариантов.
- `figures/*.png` - все графики; агрегированные графики используют средние значения и 95% доверительные интервалы, где есть повторности. Это также подписано непосредственно на графиках.

Графики строятся из уже записанных `raw.csv` и `summary.csv`; в `metadata.json` указано, из каких CSV-файлов построен каждый PNG.

## Обоснование full-параметров

- `seed = 42/43/44/46`: все запуски воспроизводимы. Разные seed по блокам разделяют случайные потоки обучения, POMO, сравнения и диагностик, чтобы не оценивать модели на той же последовательности инстансов, на которой они обучались.
- `scale = 10.0`: города сэмплируются из `[0, 10]^2`. Такой масштаб не меняет структуру оптимального маршрута по сравнению с другой постоянной шкалой, но дает длины тура порядка десятков, что удобно для policy-gradient обучения и интерпретации таблиц.
- `hidden_dim = 128`, `Attention num_layers = 3`: одинаковая скрытая размерность используется для Attention и PointerNet. Для Attention эта размерность делится на 8 голов внимания; три encoder-слоя соответствуют архитектуре, используемой в реализации Attention-политики.
- `learning_rate = 0.0001`, gradient clipping `1.0`: консервативная настройка Adam для стохастических REINFORCE/POMO-градиентов. Она снижает риск нестабильных скачков loss; лучший checkpoint сохраняется отдельно.
- `epochs = 3000`: полный запуск дает видимую динамику сходимости и не превращает воспроизведение в многосуточный расчет. Малые конфиги используются только как smoke-тест корректности запуска.
- `n_train = 20` для REINFORCE/POMO: обучение проводится на TSP-20, а сравнение на `10, 20, 50, 100, 200, 300` городах проверяет перенос на размерности вне обучения.
- `batch_size = 64` для REINFORCE: снижает дисперсию градиента при умеренном времени эпохи. `POMO batch_size = 8`, потому что `num_starts = 20` разворачивает каждый объект в 20 стартов, то есть эффективный батч равен 160 rollouts.
- `instances_per_size = 100`: в масштабировании дает доверительные интервалы по каждому размеру и удерживает LKH-часть в разумном времени.
- `exact_max_n = 10`: Held-Karp имеет экспоненциальную сложность `O(n^2 2^n)`, поэтому точное решение используется только для малых TSP. Для больших размерностей `reference_solver = exact_or_lkh` использует LKH.
- `lkh_scale = 1000000`: LKH принимает целочисленную матрицу расстояний; множитель `10^6` сохраняет шесть знаков после запятой для евклидовых расстояний.
- `permutation_instances = 100`, `permutations_per_instance = 5`: эквивариантность проверяется на TSP-20 и дает 500 парных сравнений маршрутов.
- `noise_sigmas = [0.0, 0.1, 0.2, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 4.0, 5.0]`, `noise_instances = 500`: сетка покрывает переход от слабого до сильного геометрического возмущения; 500 инстансов нужны для устойчивых доверительных интервалов.
- `entropy_sizes = [20, 30, 50, 100]`, `entropy_instances = 300`: размер 20 проверяет область обучения, 30/50/100 проверяют перенос; 300 инстансов на размер нужны для устойчивой оценки Pearson r.
- `entropy_stochastic_samples = 8`: восемь стохастических декодирований дают оценку дисперсии длины маршрута без чрезмерного удорожания эксперимента.
- `reward-noise train_size = 20`, `n_train = 64`, `sigma_rel_values = [0.0, 0.01, 0.05, 0.1, 0.2]`: обучение остается на TSP-20; 64 обучающих инстанса на эпоху согласованы с REINFORCE batch size; уровни шума идут от контрольного нуля до заметной, но не полностью разрушающей награды.

## Проверка

```bash
PYTHONPATH=src python3 -m pytest -q
```

Предупреждение PyTorch про odd `num_heads` в тесте нестандартного hidden dimension допустимо и не влияет на результаты.
